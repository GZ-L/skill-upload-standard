# 技能上传规范

本规范适用于上传到 GitHub 的 Codex / Agent Skill。它要求每个被上传的 Skill 都必须配套一份专业说明，避免仓库只有代码或提示词，后来无法判断来源、用途、安装方式和效果边界。

## 1. 上传前必须判断类型

先给被上传 Skill 定性：

- 原创 Skill：由你或团队从零设计。
- 改造 Skill：基于已有 Skill、文章、课程、项目或提示词修改。
- 第三方项目安装说明：不拥有软件本体，只写安装和使用说明。
- 私有工作流 Skill：包含个人工作流、账号方法、内容制作流程或团队规范。
- 模板型 Skill：用于生成某类文件、脚本、文档或内容。

不同类型的说明重点不同，但都必须写清楚来源和边界。

## 2. README 必须回答的问题

`README.md` 必须回答：

1. 这是什么。
2. 它解决什么问题。
3. 谁适合用。
4. 什么时候触发。
5. 输入是什么。
6. 输出是什么。
7. 怎么安装。
8. 怎么使用。
9. 效果怎么样。
10. 有哪些边界和非目标。
11. 来源是什么。
12. 怎么验证。
13. 许可证或版权边界是什么。

如果 README 太长，可以把细节拆到 `docs/INSTALL.md`、`docs/USAGE.md`、`docs/VALIDATION.md`，但 README 必须给出清晰入口链接。

## 3. 来源说明规则

必须明确写出来源类型：

- `原创`：说明作者或账号。
- `改造自`：写原仓库、原作者、原链接和改造范围。
- `对标`：写对标账号、仓库、网站或产品，并说明没有复制未授权内容。
- `第三方安装说明`：写官方来源和许可证，不上传软件本体。
- `内部工作流`：说明这是个人/团队经验规范，不声称来自外部官方。

来源说明要放在 README 的显眼位置。涉及版权或再分发限制时，还要写 `NOTICE.md`。

## 4. SKILL.md 要求

`SKILL.md` 必须包含：

- YAML frontmatter。
- `name`：小写 hyphen-case。
- `description`：包含能力、触发场景、用户常用说法和不适用场景。
- 清晰的工作流。
- 资源路由：什么时候读 `references/`，什么时候运行 `scripts/`，什么时候使用 `templates/`。
- 验证方法。

`description` 是触发关键，不能只写一句泛泛介绍。

## 5. README 推荐结构

推荐标题：

```text
# Skill Name

## 这是什么
## 来源与归属
## 适用场景
## 能力与效果
## 安装
## 使用方法
## 输入与输出
## 文件结构
## 验证
## 边界与注意事项
## 许可证
```

如果是英文仓库，可以使用对应英文标题，但信息不能缺失。

## 6. 安装说明要求

安装说明必须写清：

- 安装位置。
- 复制或 clone 命令。
- 是否需要安装到 `$CODEX_HOME/skills`、`~/.codex/skills` 或其他目录。
- 是否需要额外依赖。
- 如何确认安装成功。
- 如何更新。

不要只写“下载后使用”。

## 7. 使用说明要求

使用说明必须写清：

- 触发词。
- 最小使用示例。
- 典型输入。
- 典型输出。
- 常见错误或失败情况。
- 使用者应该准备什么文件、账号、权限或上下文。

## 8. 效果说明要求

效果说明必须写清：

- 它能产出什么。
- 质量标准是什么。
- 适合什么场景。
- 不适合什么场景。
- 是否需要人工 review。
- 是否依赖外部数据、网页、账号登录态或 API。

对内容生产型 Skill，要说明风格、结构、交付物和质量门槛。

## 9. 验证要求

上传前至少做一类验证：

- 结构验证：文件是否齐全。
- 脚本验证：`bash -n`、`python -m py_compile` 或单元测试。
- 示例验证：用一个真实触发 prompt 跑通。
- 文档验证：README 是否回答必要问题。

验证命令和结果要写进 README 或 `docs/VALIDATION.md`。

## 10. 禁止事项

不要上传：

- API Key、token、cookie、私钥、`.env`。
- 未授权第三方 zip、二进制包、源码、图片、字体、音频或视频。
- 私有账号数据和不可公开的内部文档。
- 与 Skill 无关的大型缓存、构建产物、临时文件。
- 没有来源说明的搬运内容。

## 11. 发布前检查清单

提交前确认：

- README 清楚说明“这是什么”。
- 来源账号、仓库或作者写清楚。
- 安装步骤可复制执行。
- 使用方式有示例。
- 效果和边界写清楚。
- 验证命令跑过。
- 仓库没有密钥和无关产物。
- 许可证或 NOTICE 已覆盖第三方来源。
